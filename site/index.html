DataPipe testbed

Test experiments for DataPipe, for checking a deployment end to end: one written with jsPsych and @jspsych/extension-pipe, one in plain JavaScript using datapipe-client. Both stage each trial as it happens. They send real data to a real DataPipe experiment, so point them at a test deployment and a test experiment.

What to check

Create an experiment on the deployment you are testing (for the test site, sign in at datapipe-test.web.app), switch data collection on, and keep its dashboard open in another window while you run these.

  1. Clean finish (jsPsych, save as you go). The dashboard shows 1 session in progress with a running time while you work; it disappears when you finish, and exactly one file lands in storage.
  2. Abandoned tab. Close the tab half-way. Within seconds the row reads Connection lost — may resume; after 10 minutes, Stopped — being recovered; within about 15 minutes a .partial.json holding the completed trials appears in storage and the row is gone.
  3. Brief dropout. In DevTools, set the network to Offline for about 30 seconds, then back online, and finish. The row flips to Connection lost and back; you get one complete file and no partial.
  4. Failed final submission (tick Make the final submission fail). The page claims the filename first, so DataPipe refuses the real submission as a duplicate. The log shows the save failed; the staged trials come back as a .partial.json within about 15 minutes, not 24 hours. Note the partial carries a hash suffix, because the plain filename is taken.
  5. Ended early (set Abort at trial to something below your trial count). The experiment stops as a failed attention check would. The data is still submitted — this is the behaviour a save trial never had, because an aborted timeline never reaches one.
  6. Baseline without streaming (untick Save as you go). One file, and no in-progress row at any point.
  7. Plain JavaScript, streaming. The same recovery behaviour with no framework at all — an in-progress row while it runs, one file at the end. This was impossible until the staging client moved out of the jsPsych plugin.
  8. Plain JavaScript, conditions. With Request a condition ticked, the log shows the assigned number. Switch condition assignment off on the dashboard and run again: the page reports that getCondition threw and refuses to start, rather than running an unassigned participant.
  9. Duplicate rejection. On the plain JavaScript page, Send the same file again is refused.
  10. Closed experiment. Switch data collection off and run the jsPsych test: the log reports that no session was started and the final submission is refused with DATA_COLLECTION_NOT_ACTIVE.

Tests @jspsych/extension-pipe 0.2.0 and datapipe-client 0.1.0, both loaded from the CDN, pinned.
